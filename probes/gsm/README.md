# Vortex through Yosys and sv2ghdl's gen_statemachine (2026-09-03)

Two more legs of the chain exercised on the sv2v-flattened Vortex designs
(`probes/alutest/alu.v` recipe, `probes/exectest` Tier A/B `exec.v`):

1. **Baseline Yosys synthesis** (`synth_alu.ys`, `synth_exec.ys`, results in

   26,181 gates / 3,696 flops. RTLIL and gate-level Verilog are what the P3
   NCL mapper would consume.

   `gpubuild` ships to GPU farms): ALU 189 cells / 2 registers in 0.5 s,
   execute stage Tier A 1,092 cells / 66 registers in 4 s, Tier B (soft FPU)
   13,977 cells / 168 registers in 19 s.

## Bug found and fixed: partial-slice store in emit_wide_cell

Before the fix the replay failed on AND/OR/SLL with lane 1 = 0: a per-lane
`always @* case` writing `r[i]` becomes a `$pmux` whose B port is a >64-bit
concatenation, so the cell takes the WIDE emitter, which stored a single-chunk
Y with `wire = wslice64(_wy,0,yw,ng)` -- dropping the chunk's offset and
clobbering the other lane. The scalar emitter already routed partial slices
through its scatter; the wide emitter only did so for multi-chunk Y.
`01-gen_statemachine-partial-slice-store.patch` (committed as sv2ghdl
`ad031b1`) extends `y_scatter` to a single partial chunk (the scatter branch
performs the correct RMW at the chunk offset). Minimal repro `repro/slicecase.v`
+ `repro/h_slicecase.c`: `slicecase` (two case writers) failed, `sliceplain`
(no case) and `slicesingle` (one writer) passed; all pass after the patch.

## Execute stage through the C model: verdict

`gen_gsm_harness.py ports_tierA.txt exec.c harness_exec.c` generates a replay
harness for any wrapper from its port manifest (the exectest vector layout:
inputs as nibble-padded hex, outputs as nibble-padded `%b`, inputs then
outputs in manifest order, `reset` recorded as an input, the oracle's
pre-history edge replayed before row 0). Against the committed vectors, with
the models generated by the final gen_statemachine from the `exec.v` of a
fresh `probes/exectest/run.sh tierA|tierB` (ports identical to
`ports_tierA.txt` / `ports_tierB.txt`, `exec.v` byte-identical to the previous
pass's):

    Tier A: PASS: 210 cycles replayed through the gen_statemachine model, 0 mismatches
            (1,092 comb cells, 66 registers, 4.1 s; gcc -O1 26 s; evidence/exec_tierA_gsm_replay.log)
    Tier B: PASS: 641 cycles replayed through the gen_statemachine model, 0 mismatches
            (13,977 comb cells, 168 registers, 19.4 s; 56 MB of C, gcc -O1 194 s; evidence/exec_tierB_gsm_replay.log)
    ALU:    PASS: 42 cycles, 27 results, 7 branches, 0 mismatches   (evidence/alu_replay.log)

**The "execute residual" is closed: there is no mismatch on any row of any of
the three replays, and no emitter defect remained to fix.** Every wrapper
output (43 / 46) is compared bit-exact on every row from cycle 0, x =
don't-care -- the whole execute stage including the soft FPU (all 106 FPU
commits of Tier B) is cycle-exact through vvp, NVC **and** the C model. The
compare is not vacuous: the three single-bit mutants of `vectors.txt` from
`probes/exectest` (rows 0, 1 and 13) each fail with exactly one mismatch. The
models emitted by the final binary are byte-identical to those of the
previous pass's binary for all three designs (the parameter-loop change below
does not touch the no-parameter CLI path).

The first replay's 10 mismatches (4 at cycle 0, 6 at cycles 12/13/15) had two
causes, neither a new defect:

**Cycles 12/13/15 were the slice-store bug above.** The replayed `exec.c` had
been generated *before* the fixed binary was built. Bisected by dumping every
internal comb signal of both models (`-DSM_DUMP`, `sm_dump_comb`) per cycle
with the identical harness (`evidence/exec_tierA_bisect_c10.diff`): cycles 0-2
identical; cycles 3-9 differ in exactly one signal, `alu_int.msc_result`
(unconsumed); cycle 10 is where it propagates -- the AND at PC 0x105
(`alu_in1 = 1234f0f0_f0f0f0f0`, `alu_in2_imm = ffff0ff0_0ff00ff0`, identical in
both) gives `msc_result = 0000_1234` in the old model instead of
`0000_1234_00f0_00f0`: lane 1's value stored at lane 0, lane 1 cleared, exactly
`repro/slicecase.v`. From there `alu_result[63:32]`, the `rsp_buf` pipe register,
`pe_switch`/`lane_gather` and `commit_if_0_data` lane 1 follow. The three rows
are the AND / ORI / SLL commits (PC 0x105/0x106/0x108, `decode_commits.py`),
not branches; `branch_ctl_if_0_dest` is wrong on the same rows because with
`valid = 0` it still carries `br_dest = from_fullPC(br_result)` with
`br_result = alu_result_r[last_tid]` (lane 1) -- `0x1234 >> 2 = 0x48d`,
`0x0f0f >> 2 = 0x3c3`, `0x10 >> 2 = 4`, the recorded values. The pre-fix
binary (`ad031b1^`) rebuilt from git reproduces the 6 mismatches with today's
harness (`evidence/exec_tierA_prefix_model.log`) and fails `slicecase.v`; the
elastic-buffer / `pe_switch` / wide-mux paths suspected earlier are all correct.

**Cycle 0 was the harness, not the model.** The exectest oracle
(`tb_exec.sv.in`: `reg clk = 0; always #5 clk = ~clk`, `reset = 1` from t0,
row 0's inputs driven from t0, recorder 1 ns after each negedge) samples row 0
at 11 ns, *after* the first rising edge at 5 ns; row k therefore follows k+1
posedges with inputs in0, in0, in1, ..., in(k-1). The NVC replay bench
reproduces that pre-history; the C harness compared row 0 against the bare
`sm_reset` state and only got away with it from row 1 on because reset is
asserted for rows 0-1 (a second reset edge is idempotent). The four row-0
outputs were the `VX_stream_buffer` `valid_in_r` flags that reset to 1
(`dispatch_if_1/2_ready` = the LSU/SFU `lane_dispatch` output buffers,
`lsu rsp_ready` = the LSU slice's `rsp_buf`) and `trap_cause` (recorded `x011`: the
merge of 3 and 11 under an x `br_op_r`; the model's 1011 agrees on the defined
bits). `gen_gsm_harness.py` and `harness_alu.c` replay that edge (`if (cyc == 0)
sm_clock(&st, &in)` before the row-0 compare), and the ALU rows 0-3 that were
skipped before are compared too. It is *not* a model defect: `sm_reset`
already applies yosys `init` attributes (declaration initialisers) and `$adff`
reset values, and exec.v has neither (Vortex is sync-reset, no initialisers
under `SYNTHESIS`). Repro `repro/prehist.v` + `tb_prehist.v` + `run_prehist.sh`
(`evidence/prehist_repro.log`): a sync-reset `ready` that resets to 1, a
`reg [7:0] cnt_r = 5` counter with no reset, an un-reset `q <= a`, and an
x-forever register -- the previous generator fails `ready`/`q` on row 0 and
`cnt` on every row (14 mismatches); the current one passes all 12 rows. The
genuine, unavoidable time-0 difference is confined to what the oracle never
samples: before the first edge un-reset registers are x in vvp and 0 in the
model; after the reset edge their defined bits agree (x-monotonicity) and their
x bits are don't-care. The pre-history edge is specific to benches with the
exectest/alutest alignment (documented in the generated comment); a vector
file recorded before the first posedge would need it disabled.

### The gaps that stood in the way, and their fixes

The first attempt (`evidence/accel_alu_run.log`) installed nothing: the
walker declined (`T_FCALL`), then the text path failed with `Module
'vx_pipe_register1' not found` and `chparam NUM_LANES = 2 on VX_gpu_pk`.
Fixes, in `nvc/src/rt/model.c` (`03-nvc-accel-text-path.patch`) and
`sv2ghdl/yosys/gen_statemachine.cpp` (`02-gen_statemachine-chparam-default.patch`),
each with a minimal repro (`repro/accel_modname/run.sh`, `run_before|mid|after|final.log`
= pre-fix nvc, fixes 1+2 only, all fixes, final build; `repro/gsm_chparam_default`;
`repro/gsm_keep_stale_default`; `repro/accel_modline`):

1. **Entity name != Verilog module.** tgt-vhdl emits one entity per
   parameterisation (`VX_pipe_register`, `VX_pipe_register1`, attributes
   `nvc_verilog_src "alu.v:2370"`, `nvc_verilog_params "DATAW=152 ..."`); the
   synth top was `vhdl2vlog_variant_name()` = the lowered entity name, which
   yosys (case-sensitive) does not have. `accel_verilog_module()` reads
   `module <name>` at the `nvc_verilog_src` line and `accel_install_subtree`
   uses it as the synth top when not `FROM_VHDL` (`accel-jit: entity
   'vx_pipe_register1' is Verilog module 'VX_pipe_register'`). Review
   follow-up (`repro/accel_modline`): the line was located by counting
   `fgets()` chunks of 4096 bytes, so physical lines longer than that (sv2v
   emits multi-KB packed localparam lines) shifted the 4-line window onto
   the PREVIOUS module's header -- `modline.c` holds both scanners verbatim:
   on `modline.v` (four 5 KB comment lines, `decoy` right before `PTop`) the
   old one names `decoy`, the new one `PTop`; a `module automatic X` header
   named the module `automatic` (now skipped; yosys' `read_verilog` rejects
   the lifetime keyword anyway, so that case is scanner-only). And a guard:
   the module name is accepted only if its lowercase form is a prefix of the
   entity name (module + tgt-vhdl's numeric suffix), otherwise the variant
   name is kept and yosys declines instead of synthesizing a different module
   against the entity's ports -- `run.sh` step 3 points the attribute at the
   decoy's header and gets `entity 'ptop' vs Verilog module 'decoy' at the
   nvc_verilog_src line: not its module -- ignored`, `Module 'ptop' not found`,
   the three `VX_preg` leaves install instead, PASS.
2. **`chparam ... on VX_gpu_pk`** was not a tokenizer bug: the
   `nvc_verilog_params` attribute was read into `char params[256]` (alu_top's
   is 700 bytes, exec_top's 1,514 / 58 tokens) and cut mid-token; the tail
   `VX_gpu_pk` had no `=`, so gen_statemachine's argv parser took it for the
   top module. The attribute is now read into a malloc'd string, the fork
   argv and the CLI command are sized by their contents (the 150/158-token
   caps are gone), and the actuals are folded into the synth cache key.
3. **`chparam` of a value equal to the module default** re-derives the module
   from its AST, and in the derived copy sv2v's hierarchical reference by
   module name inside a function argument
   (`sv2v_cast_4(alu_top.execute_if.data[222-:4])`, alu.v:3871/3875) no
   longer resolves: `Failed to detect width for identifier
   \alu.alu_top.execute_if.data`. gen_statemachine now keeps the parsed module
   for an override equal to its default (`keep NUM_LANES = 2 (default of
   alu_top)`) and filters the localparams whenever the top was found (the old
   `!settable.empty()` test passed everything through for a top with no
   `parameter`, which then aborted in yosys). A genuinely different value on
   that shape still fails inside yosys (`repro/gsm_chparam_default`, N=3) --
   a yosys limitation, not hit by the Vortex tops (their actuals equal their
   defaults). **Review fix (both reviews, high + medium)**: the first version
   compared against a snapshot of `parameter_default_values` taken before any
   `chparam`, but a default may derive from another parameter (`parameter
   RESETW = DATAW`, the `VX_pipe_register` shape; 15 such headers under
   `hw/rtl/libs`) and every `chparam` re-derives the module, so an override
   that merely coincided with the stale default was silently dropped (`dep.v`
   `DATAW=4 RESETW=1`: all four bits reset instead of bit 0). The default is
   now read from the LIVE module on every test, the kept overrides are
   re-tested after the loop and any whose default drifted is applied, sweeping
   until none drifts (`keep RESETW = 1` ... `chparam RESETW = 1 on dep
   (default drifted)`); the value is parsed base 10 (chparam's own decoding;
   `strtoll(,0)` read `010` as octal) with overflow rejected and compared at
   >= 64 bits with the default extended by its own signedness, so
   `BASE=4294967296` on a 32-bit default is no longer a "no-op" and nvc's
   `18446744073709551615` (`ivl_expr_uvalue` of -1) and a CLI `-1` both keep a
   signed -1 default (HEAD aborted on `-1`: `Can't decode value`).
   `repro/gsm_keep_stale_default/run_cases.sh` (`run_cases_final.log` vs
   `run_cases_head.log`): `dep.v` and `chain.v` (`B = A`, `C = B`) in both
   argument orders emit models with 0 normalised lines of difference from
   HEAD's chparam-everything models; `hier.v` N=2 is kept and byte-identical
   to the no-override model where HEAD fails; all-default `dep.v` is
   byte-identical to the no-override model; the edge cases give the chparam
   values. The all-default whole-DUT tops emit the as-read module instead of
   HEAD's derived copy, which differs only in `$auto$` names, not semantics.
4. **NBA-region publication onto `:=`-written rims** (found once `alu_top`
   installed: the replay FAILed 60 rows, all on the branch outputs, which read
   the tb signal's initial value `br_taken = L` while `NVC_ACCEL_VERIFY=1`
   showed the model agreeing with the interpreter on every net and
   `NVC_ACCEL_NBA=0` passed). tgt-vhdl writes those ports with the fork's
   blocking `:=` inside fused comb processes (alu.vhd:2591-2620, `br_taken :=
   taken`), so their nexus has no driver source; the bridge publishes
   registered outputs with `sched_deposit(nonblock)` (the NBA region), which
   attaches a `SOURCE_DEPOSIT` pseudo-source, and the STD_MX "skip port with
   no real driver" walk in `calculate_driving_value` / `source_value` -- which
   admitted a deposit-written rim only through `n_sources == 0 && last_event`
   -- then found no `SOURCE_DRIVER`, skipped the port source and put the
   reader's initial value. Comb outputs use the immediate `deposit_signal`
   (no pseudo-source) and `<=`-driven ports keep a quenched `SOURCE_DRIVER`,
   which is why `ex_ready`/`rs_valid`/`rs_data` were right. Both twin walks now
   count a `SOURCE_DEPOSIT`/`SOURCE_FORCING` pseudo-source as a value source.
   Regression on that change: all eight `nvc/test/accel/*_run.sh` cases MATCH
   on the final binary (`evidence/nvc_test_accel.log`) and NVC's own
   `test/regress` suite shows no difference against the pre-fix binary (below).

Still open on this path, by design or out of scope: the RTLIL walker's
`T_FCALL` decline; yosys' `chparam` on the sv2v function-argument
hierarchical-reference shape with a genuinely different value; tgt-vhdl
records only numeric actuals in `nvc_verilog_params` (review, low: two
variants that differ only in a string or real parameter would synthesize the
default one -- Vortex's string parameters such as `INSTANCE_ID` are trace-only,
so not live here; the fix belongs in `iverilog/tgt-vhdl/scope.cc`, untouched);
`NVC_ACCEL_PER_INSTANCE` leaf variants and non-default DUT wrappers are exactly
the actuals-differ-from-defaults case the keep-default fix protects.
